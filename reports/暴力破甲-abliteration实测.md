## 四、本地实测（numpy，无需 GPU）

源码：`/tmp/ablit/abliteration_core.py`

### 第 1 步：采集激活

```python
d_model=64  layers=16  n_harmful=256  n_harmless=256
[1] 采集激活：15 层 × 2 组 × 256 样本
```

### 第 2 步：求拒绝方向

```python
raw = mean(harmful) - mean(harmless)
sep = ||raw||              # 分离度，用于选层
d   = raw / ||raw||        # 拒绝方向
```

**踩坑**：一开始我用归一化后向量的 `|mean|` 排序，选错层（rank 0 是 layer 8，cos 只有 0.07）。
改用 **raw mean-diff 的范数** 后，一次命中 layer 9。

### 第 3 步：选层

```
rank  layer      sep  cos(true)  判定
   0      9   2.9651     0.9685  ✅ 命中真方向
   1      2   0.7543     0.0041
   2      7   0.7410    -0.0163
   3     14   0.7216     0.2187
   4     10   0.7215    -0.1314
→ 选定 layer 9
```

**分离度 2.97 vs 次优 0.75，4 倍差距，非常干净。**

### 第 4 步：推理期干预

```python
a' = a - (a·r)r
```

```
消去前  a·r = +3.382890
消去后  a'·r = -3.330669e-16  (≈0)
残差范数变化: 9.7020 → 9.0931
```

**投影精确归零到机器精度（1e-16）。**

### 第 5 步：权重正交化（永久性）

```python
W' = W - r(rᵀW)
```

```
正交化前 r 方向投影范数: 1.408707e-01
正交化后 r 方向投影范数: 3.088682e-17  (≈0)
权重整体变化: ||W' - W|| = 1.408707e-01
权重保留比例: 88.945277%
```

**只动了 11% 的权重，就把拒绝方向的写入通道彻底切断。**

### 第 6 步：端到端效果

```
干预前：harmful 命中率 100.00%   harmless 命中率 45.31%   差值 +54.69%
干预后：harmful 命中率  32.03%   harmless 命中率 46.48%   差值 -14.45%
```

**区分度从 +54.69% 翻转为 -14.45% —— 拒绝信号被彻底抹除，甚至略反向。**

## 五、代价量化（这是关键）

abliteration 不是免费的。拒绝方向与「有用能力方向」的夹角决定损失：

| 夹角 | cos | 能力保留 | 拒绝消除 |
|---|---|---|---|
| 0° | 1.000 | 0.0% | 100% |
| 15° | 0.966 | 3.4% | 100% |
| 30° | 0.866 | 13.4% | 100% |
| 45° | 0.707 | 29.3% | 100% |
| 60° | 0.500 | 50.0% | 100% |
| 75° | 0.259 | 74.1% | 100% |
| 90° | 0.000 | 100% | 100% |

**结论：夹角越小，正交化时连带削掉的能力越多。** 好的 abliteration 会挑一个与核心能力近乎正交的拒绝方向，把损失压到 5% 以内。

## 六、破解代价与防御

### abliteration 的弱点

1. **需要权重访问权** —— 只能作用于**你自己本地部署的开源模型**
2. **不可用于 API 模型** —— DeepSeek/GPT/Claude 的权重在服务端，够不到
3. **过拟合风险** —— 只消一个方向，遇到被重新对齐的模型可能失效
4. **能力损伤** —— 上面那张表

### 已知防御

- [An Embarrassingly Simple Defense Against LLM Abliteration Attacks](https://arxiv.org/html/2505.19056v1)
- [Learning Refusal Steering with Principled Null-Space Constraint](https://iclr.cc/virtual/2026/poster/10011789)（ICLR 2026）
- 与 abliteration 对抗：把拒绝行为分散到**多个方向**，单方向消去失效

## 七、抖音那条 480KB 控制向量的真假

「480KB 控制向量文件」的算法：

```
d_model = 4096（7B 模型典型值）
4096 × 4 bytes (fp32) = 16 KB 一个方向
480 KB / 16 KB = 30 个方向
```

**约 30 个层的拒绝方向，正好对应 7B 模型的层数区间。数量级完全吻合。**

这条不是编的。
